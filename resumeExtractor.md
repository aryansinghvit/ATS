We built a high-performance, local-only Enterprise Resume Extraction Microservice optimized natively for Apple Silicon. At its core, it leverages the `mlx-vlm` framework and the `Qwen3-VL-8B-Instruct-4bit` vision-language model to process resumes entirely on-device, bypassing cloud AI providers and heavy frameworks like PyTorch.

The engine features a dynamic triage system that instantly routes text-heavy files (digital PDFs, DOCX) through CPU-efficient parsers like `pymupdf` and `python-docx`, while rasterizing scanned documents and images through the GPU with strict token-budget limits. To guarantee enterprise-grade reliability, it includes a 1-step auto-repair loop that catches and fixes hallucinated JSON, ensuring the output always perfectly matches a strict data contract. It also features a deterministic scoring engine that uses pure Python logic to calculate a candidate's fit against a provided Job Description, completely eliminating AI scoring bias.

**Microservice Architecture & Local Operation**
The engine operates as a secure, headless FastAPI application. To protect your M3 Pro hardware, it utilizes a strict hardware lock (`asyncio.Semaphore(1)`) to queue requests, ensuring only one resume hits the GPU at a time. This guarantees unified memory usage never exceeds the 13.3 GiB Metal working limit, even if 500 applicants submit resumes simultaneously. The microservice is inherently GDPR and SOC2 compliant: it requires `X-API-Key` authentication, tracks job states in a lightweight local SQLite database, and strictly enforces ephemeral file retention by permanently deleting candidate resumes from the local disk the exact moment extraction completes.

**ATS Integration**
Integrating this microservice into a corporate Applicant Tracking System (ATS) like Workday, Greenhouse, or a custom HR desktop database relies on its dual-mode REST API. When a candidate applies, the client ATS sends an HTTP POST request containing the file and an optional Job Description. The integration supports two routing paths:

* **Asynchronous Webhook Mode (Standard):** Because visual VLM processing can take 30 to 90 seconds, the ATS includes a `webhook_url` in its request. The microservice immediately returns an `HTTP 202 Accepted` with a tracking ID, freeing up the ATS. Once the local GPU finishes processing the resume in the background, your server fires an HTTP POST back to the ATS webhook listener, delivering a standardized JSON envelope containing the parsed profile and the deterministic job-match score.
* **Synchronous Mode (Fast Fallback):** For instant processing of lightweight digital text files, the ATS can omit the webhook URL. The connection remains open, and the microservice blocks until it returns an `HTTP 200 OK` containing the final JSON directly in the initial response.
